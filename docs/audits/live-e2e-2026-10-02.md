# Live System Audit: 2026-10-02

Target: https://remoteimpact.org/

## Outcome

Confirmed defects were fixed and deployed through `/opt/easyclaw/deploy.sh fast`.
Final automated results: 86 live public/catalogue checks passed, 30 authenticated
production-flow checks passed, and 194 focused regression tests passed. Django
system checks and `git diff --check` passed. These results describe the scenarios
tested, not a guarantee that every possible workflow or listing is correct.

## Defects Fixed

- Untouched salary controls submitted bounds that excluded jobs without salaries.
  Default lower/upper endpoints now mean unbounded; the frontend omits them.
- Salary sorting was performed after pagination. Sorting now happens across the
  database queryset, including searches, with null salaries last and stable ties.
- Pagination lost repeated category/type parameters. Encoded QueryDict values
  now preserve all selected filters; search submissions retain the sort setting.
- Personalized results with no matches fell back to featured-first ordering.
  The fallback now uses newest posted date first, with a stable ID tie-breaker.
- Country aliases split equivalent searches. USA/US/United States and
  UK/United Kingdom resolve consistently; bounded location matching avoids
  incidental matches such as India in Indiana. Global aliases do not include
  every listing merely labeled Remote.
- Scouts requesting a specific technical stack could accept a role without
  evidence of that technology. Technical role briefs now require supporting
  title/description/requirements evidence rather than tags alone.
- Cross-source ATS duplicates escaped detection when organization names or URL
  tracking parameters differed. Unique Ashby/Lever/Greenhouse posting identifiers
  now drive safe matching. Different posting IDs and generic board URLs remain
  distinct. The richer-quality record is retained.
- The homepage Scout editor was capped at 400 characters despite longer briefs
  being supported downstream. It now accepts 2,000 with a matching counter.
- The Scout preview pluralization rendered "matchs"; it now renders "matches".

## Safety and Unverified Boundaries

Authenticated QA data and delivery records were created inside a transaction
and rolled back; the synthetic QA user was verified absent afterward. Email
transport was mocked: rendering and delivery bookkeeping were tested, but real
inbox receipt and deliverability were not. The recurring sender was dry-run.
No real user was emailed, no real payment was charged, and no subscription was
created. Stripe live-key configuration was checked, not a completed real
checkout/webhook. Third-party OAuth and every employer/gig workflow were not
fully exercised. Source URLs were sampled, not exhaustively validated.
